# Техническое задание

Разработать на C++17 контейнер на основе AVL-дерева для лабораторной работы 1.
Текущий этап включает операции дерева и поддеревьев, множество на дереве, перегрузку операторов,
интерактивный интерфейс, вывод структуры, проверку инвариантов и исследование производительности.

## Структура и типы

`Tree<T, K>` задаёт общий интерфейс, `BinarySearchTree<T, K>` хранит узлы через
`std::unique_ptr`. Ключ K определяет положение узла, значение T хранится независимо.
Разные ключи могут иметь одинаковые значения. Значения копируются при вставке,
для Reduce также требуется присваивание. Конструктор по умолчанию и сравнение
значений базовым операциям не нужны. Поиск поддерева использует `==` для значений
или переданную функцию проверки равенства. Вспомогательный DynamicArray требует конструктора
по умолчанию и копирующего присваивания элементов.

Компаратор ключей должен задавать неизменный строгий слабый порядок. По умолчанию
используется `<`: trait IsLessComparable и static_assert проверяют при компиляции
его доступность для константных ключей и преобразуемость результата в bool.
Эквивалентными считаются ключи, для которых компаратор возвращает
false в обоих направлениях. Проверка `compare(key, key)` при вставке не доказывает
все свойства компаратора. Вещественные NaN не допускаются как ключи с обычным `<`.
С собственным компаратором ключам не обязательно иметь оператор `<`.

## Операции

- Insert добавляет новую пару и возвращает true. Для существующего ключа возвращает
  false и сохраняет прежнее значение.
- Contains проверяет наличие ключа. Get возвращает константную ссылку на значение.
  Отсутствующий ключ в Get и доступ к корню пустого дерева вызывают out_of_range.
- Remove удаляет пару по ключу, возвращает false при отсутствии ключа.
- В BinarySearchTree оператор [] читает значение через Get, не добавляя отсутствующий ключ.
  Оператор += вставляет пару «ключ — значение» через Insert и возвращает ссылку на дерево;
  повторный ключ сохраняет прежнее значение.
- GetSubtree в BinarySearchTree возвращает независимую копию узлов с заданным корнем,
  сохраняя ключи, значения, связи, высоты и компаратор. Отсутствующий корень вызывает out_of_range.
- ContainsSubtree проверяет точное совпадение структуры и значений. Ключи сравниваются
  на эквивалентность компаратором исходного дерева. Пустое поддерево входит в любое дерево.
  По умолчанию значения сравниваются через ==; можно передать собственную функцию.
  Нулевой указатель на неё вызывает invalid_argument. Эти операции не меняют исходное дерево.
- Clear освобождает все узлы. GetCount и GetHeight возвращают сохранённые характеристики.
  Высота пустого дерева — 0, листа — 1.
- После вставки и удаления поддерживаются порядок BST, правильные высоты и разность
  высот потомков не более 1. IsValid проверяет эти свойства и количество узлов.
- GetEnumerator поддерживает КЛП, КПЛ, ЛКП, ЛПК, ПЛК, ПКЛ; по умолчанию — ЛКП.
  Traverse выполняет действие над каждой парой в выбранном порядке.
- Map преобразует значения T в T, Where отбирает значения. Ключи и компаратор сохраняются,
  результат строится как независимое AVL-дерево; исходная форма не гарантируется.
- Reduce последовательно вычисляет func(значение, аккумулятор), начиная с переданного
  начального значения. Map, Where и Reduce используют ЛКП.
- Print выводит корень и ветки с ключами и значениями через переданную функцию форматирования.
  Корень находится на уровне 1. Глубина и число показанных узлов ограничиваются;
  при сокращении выводится фактически показанное количество. Нулевые ограничения запрещены.

Нулевые указатели на функции, некорректный порядок обхода и ограничения вызывают
invalid_argument. Доступ к текущему элементу до начала и после конца перечисления
вызывает out_of_range. Успешное изменение дерева инвалидирует перечислители;
последующий доступ вызывает logic_error. Неуспешная вставка или удаление их не инвалидирует.
Дерево должно существовать дольше перечислителя. Обработчики не должны изменять
обрабатываемый контейнер. Ссылки на удалённые элементы становятся недействительными.
Исключения пользовательских функций передаются вызывающему коду.
Копирование и перемещение дерева текущий интерфейс не предоставляет.

## Множество

Реализовать Set<T> на основе BinarySearchTree<bool, T>. Элемент хранится один раз
как ключ, bool является служебным значением. Требуются копирование элементов
и строгий слабый порядок, по умолчанию заданный <. С пользовательским компаратором
элементам не нужны операторы < и == или конструктор по умолчанию.

Insert, Remove и Contains используют операции дерева. Повторная вставка и удаление
отсутствующего элемента возвращают false. GetCount возвращает количество, IsEmpty —
признак пустоты, Clear удаляет все элементы. Print выводит элементы по компаратору
в фигурных скобках; по умолчанию показывает не более 100. Нулевой предел запрещён,
при сокращении добавляется многоточие. Только Print требует вывода T в поток.

Union, Intersection и Difference строят новые независимые множества. IsSubsetOf
проверяет наличие всех элементов текущего множества в другом. Equals проверяет
равенство наборов независимо от структуры дерева. Пустое множество включено в любое.
Дубликаты и равенство элементов определяются компаратором, а не оператором ==.
В Union эквивалентный элемент первого множества сохраняется; Intersection и Difference
используют представителей первого множества.

Для всех бинарных операций, включая проверки, указатели на компараторы должны
совпадать. Иначе выбрасывается invalid_argument даже для пустых множеств.
Нулевой компаратор при создании также запрещён. Результаты сохраняют компаратор,
входные множества не изменяются. Исключения сравнения и копирования передаются вызывающему
коду; незавершённый результат освобождается автоматически. Копирование множества
обычным конструктором и присваиванием текущая версия не предоставляет.

При постоянной стоимости сравнения и копирования вставка, поиск и удаление — O(log n).
Для n и m входных элементов и k элементов результата Union занимает
O((n + m) log(n + m + 1)), Intersection и Difference — O(n log(m + 2) + k log(k + 1)),
IsSubsetOf — O(n log(m + 2)). Equals сравнивает размеры и выполняет проверку включения.
Количество и пустота доступны за O(1), Clear — O(n). Результат занимает O(k) памяти.

## Консольное приложение

Предоставить меню операций над int-ключами и int-значениями, ручной ввод,
генерацию различающихся ключей с настройкой количества, диапазона, порядка и seed.
Показывать структуру, высоту и число узлов; для Map и Where — исходные данные и результат.
Предоставить извлечение поддерева по ключу и проверку вхождения дерева, введённого вручную.
Добавить отдельное подменю для двух множеств A и B с ручным добавлением, удалением,
поиском, очисткой, выводом и всеми операциями над множествами. Порядок аргументов
разности и включения выбирается пользователем. Наборы сохраняются между входами в подменю.
Ошибки ввода должны позволять повторить ввод, ошибки операций — вернуться в меню.
Арифметические переполнения обрабатываются исключением.

## Проверка и исследование

Модульные тесты проверяют базовые операции, повороты, инварианты после смешанных
и упорядоченных изменений, шесть обходов, функциональные операции, пользовательские типы,
инвалидирование перечислителей, генерацию, ограничения вывода, операторы и поддеревья.
Проверять сохранение структуры и независимость копий, несовпадение ключей, значений
и ветвей, пустые поддеревья и пользовательские компараторы. Выполнить запуск
с AddressSanitizer и UndefinedBehaviorSanitizer.
Для Set проверить дубликаты, пустые и непересекающиеся множества, операции с собой,
оба направления разности, равенство независимо от формы, независимость результатов,
случайные изменения, строки, пользовательские типы и несовпадающие компараторы.

Измерить построение, поиск, обход и удаление на нескольких размерах больших
и очень больших наборов. Бенчмарк поддерживает размеры до 10⁸; в отчёте указывать
реально выполненные эксперименты. Сохранять каждый повтор и строить графики медиан
времени от числа узлов для трёх порядков входных данных.

При постоянной стоимости сравнения и обработки значения поиск, вставка и удаление
занимают O(log n), обход и Reduce — O(n), Map — O(n log n), Where — O(n + m log(m + 1))
для m выбранных узлов. Количество и высота доступны за O(1).
Извлечение и поиск поддерева занимают O(log n + m), где m — число его узлов.
Для копии требуется O(m) дополнительной памяти. Операторы имеют сложность Get и Insert.
AVL поддерживает логарифмическую высоту, а обычное BST может выродиться на упорядоченном вводе.
Перечислитель использует стек высотой O(log n); прошивка в этой версии не реализуется.

Объём существующих рейтинговых операций — 23 единицы и предполагаемые 3 за IEnumerable
с перечислителем, соответствие которого нужно сверить с ЛР-2. Из них операторы дают 2,
извлечение поддерева — 2, поиск поддерева — 3. Множество добавляет 6: базовые операции — 2,
объединение, пересечение и разность — 2, включение и равенство — 2.
При зачёте IEnumerable получается 26 единиц, что превышает обычный минимум 25.
